# swift-eu-eli

Use this package when you build or read a European Legislation Identifier: an HTTP URI, such as `http://data.europa.eu/eli/reg/2016/679/oj`, that names an act from its components. Start from `ELI(eu:)` for the EU's own ELIs on EUR-Lex, and from `ELI.Template` with `ELI(_:template:)` for a national publisher's. It follows the Council conclusions on ELI of 2012 (OJ C 325, 26.10.2012, p. 3) and 2017 (OJ C 441, 22.12.2017, p. 8), and the Publications Office's ELI templates for EU legislation as its ELI register page stood on its last update, 6 October 2025. A value that parses is well-formed. It is not necessarily assigned.

## Laws

- An ELI is a template and its components. The template is a base URI and a sequence of path segments: literals, components and, at most once, a run of subdivisions. `ELI.Template.uriTemplate` is the RFC 6570 template the conclusions describe, and `ELI.uri` expands it with swift-rfc-6570.
- The components are those of the conclusions' template table: jurisdiction, agent, sub-agent, year, month, day, type, sub-type, domain, natural identifier, subdivisions, point in time, version and language, with the EU's format, publication date and sequence. An ELI holds exactly the components its template names: a missing one or an extra one is refused.
- A component value, `ELI.Component.Value`, is URI unreserved characters and parentheses, and parentheses are allowed only in the natural identifier, as in `445(1)`. A sequence is digits and not zero.
- Year, month and day are one `ISO_8601.CalendarDate.Reduced`: the year is four digits and the month and day two, and the calendar must have the date, so `2016/02/30` is refused. A template naming a month names the year, and one naming a day names the month.
- A jurisdiction is an ISO 3166 alpha-2 code or, as the conclusions allow for international organisations, any other name in letters, such as `WTO`. A language is an ISO 639 code in two or three letters, kept as written. A point in time is `YYYYMMDD` unless the template uses the extended `YYYY-MM-DD`, as the EU's do.
- Parsing against a template refuses a URI with another scheme, host, port or base path, a query or a fragment, a literal that differs, or the wrong number of segments.
- `ELI(eu:)` reads the EU's templates on `http://data.europa.eu/eli`: an act's `{type}/{year}/{natural identifier}` or a treaty's `treaty/{natural identifier}`, then any subdivisions, then the version: `oj`, `corrigendum/{publication date}/oj`, `corrigendum/{publication date}/{sequence}/oj`, a consolidated version's date, a treaty's `sign`, or nothing for the abstract ELI. Any of these may end in `/{language}` or `/{language}/{format}`. `ELI.Template.eu(_:_:of:)` builds each of them.
- In the EU's ELIs a type is lower-case letters and underscores, or `C`, and a subdivision is a lower-case label, an underscore and a value, such as `art_1` or `par_2`. When several templates fit, the corrigendum comes before the Official Journal version, a language before a subdivision, and the abstract ELI last.
- The EU's partial ELIs, which list acts rather than name one, are not covered. Nor is the issue-and-item form some pre-2023 OJ C notices have, as in `C/1999/202/1/oj`, which the Publications Office's templates don't describe. The ELI ontology's metadata properties are left to the RDF that carries them.
